# Public Repository Scope

This repository is the public collaboration surface for Fleet Assurance Simulation 0.2.0. The publication boundary is deliberately narrower than the complete local release workspace.

## Included in Git history

- Python source, command-line entry points, schemas, configurations, and tests
- Stage 0 through Stage 3 protocols, architecture records, reports, decision tables, and acceptance records
- Publication figures with SHA-256 manifests, source hashes, alternative text, and provenance
- Compact Stage 2 and Stage 3 synthesis artifacts
- The immutable Stage 3 synthetic confirmatory execution, including its evidence, execution manifest, held-out predictions, and checkpoints required for reproducibility
- Small demonstration replay bundles and documentation assets that remain below GitHub's per-file limit
- Successor-study intake, calibration-gate, adapter, prospective-registration, target-free prediction-commitment, and evaluation-input-binding source
- Closed successor schemas, engineering examples, public workflow documentation, status UI, and tests

## Excluded from Git history

- Virtual environments, caches, build directories, package metadata, and local logs
- Engineering-pilot result directories, which are excluded from scientific adjudication
- Oversized offline HTML and JSON console exports, which can be regenerated from retained evidence
- Local verification scratch runs and archived working-copy repair material
- The complete local release ZIP and checksum sidecar
- Local measurement campaigns and generated intake, fit, adapter, registration, prediction-commitment, evaluation-input, custody, or result packages unless a separate public-scope review explicitly approves a sanitized artifact

The exclusions reduce accidental publication of local residue and keep the collaboration history usable. They do not change the immutable confirmatory metrics, criteria, dispositions, or evidence scope.

## Evidence and security boundary

All retained Stage 3 evidence is synthetic and model-conditioned. No external operational dataset was supplied, and no external validation was performed. The repository does not establish implementation security, deployment assurance, a universal fleet-assurance law, or a secure fleet-size recommendation.

Do not add proprietary, classified, export-controlled, personal, operationally sensitive, or third-party restricted data. Report suspected vulnerabilities through the private process in `SECURITY.md`.

The successor workflow accepts public or synthetic inputs only. Its generated packages stay under `local_runs/`, which Git ignores. Prospective registration additionally requires nonsynthetic calibration evidence and an evidence-backed adapter, but that stricter input gate does not make generated evidence public by default.

The registration, prediction-commitment, and evaluation-input packages record declared timestamps with internally consistent ordering and bind exact digests, campaign identities, collection windows, cells, time-block IDs, block timestamps, fleet sizes, admission counts, observation windows, and target-free prediction rows. They do not establish package creation or publication time, provide external timestamp attestation, prove that people or outside systems lacked target access, authenticate the collecting organization, authorize the runner, or establish scientific or external validation. A hash proves integrity, not publication approval, provenance authority, trusted timing, custody, or operational readiness.

Only the ten-resource arrival-rate transfer contract is implemented. Operational-outcome transfer is disabled and must not be implied by public documentation or UI states.

## Future public interface

A GitHub Pages interface is a later product milestone, after the successor workflow and evidence contracts stabilize. Publication requires a clean-checkout build, accessibility and responsive-layout checks, an offline/no-secret review, verified links from every displayed claim to immutable public evidence, and explicit release authorization. A public view must distinguish target-free local commitment from independently attested pre-outcome custody, keep outcome-release and scoring blockers visible, and show false authorization states directly. Negative and not-evaluable results must remain visible; the site must not imply operational approval, external validation, scientific support, or deployment readiness.
